## 模块一：微调 vs RAG vs Prompt（灵魂拷问）

### Q1　微调、RAG、Prompt Engineering 三者的本质区别是什么？

- 🔵 考察点：是否理解三者改变了什么（权重 / 上下文 / 仅输入）、知识存储位置、成本与更新速度的 trade-off
- 🟢 参考答案要点：① Prompt 不改模型，只改输入；② RAG 改上下文，知识在外部向量库；③ 微调改权重，知识刻进模型；④ 成本从低到高：Prompt < RAG < 微调；⑤ 更新速度从快到慢：Prompt > RAG > 微调
- 🟡 加分项：能画出决策树（知识新鲜 → RAG，格式固化 → 微调，快速验证 → Prompt）；能说出"RAG 解决知道什么，微调解决怎么想"；能举出组合使用的实际场景
- 🔴 危险信号：认为三者可以互相替代；认为微调成本低；认为 RAG 不需要向量库

### Q2　什么时候该上微调？给出三个信号。

- 🔵 考察点：是否理解微调的触发条件，而非"什么都微调"或"永远不微调"
- 🟢 参考答案要点：① Prompt 调了很多轮效果仍不达标；② 任务需要稳定的格式/风格输出（Prompt 兜不住）；③ 有足够的高质量标注数据（≥1000 条）
- 🟡 加分项：能结合具体场景量化"Prompt 调了很多轮"（如 5-10 轮迭代仍不稳定）；能说出不同任务的数据量门槛差异（工具对齐 200-500 vs 领域问答 1000-3000）
- 🔴 危险信号：认为"有数据就该微调"；认为"微调能解决一切问题"；忽略数据质量只谈数量

### Q3　RAG 和微调能互相替代吗？为什么？

- 🔵 考察点：是否理解两者的互补关系而非替代关系
- 🟢 参考答案要点：① 不能替代；② RAG 管知识 freshness，微调管行为 pattern；③ 知识频繁更新的场景（股价、文档）RAG 是唯一解；④ 需要深层领域推理的场景微调是唯一解
- 🟡 加分项：能举出"RAG 给信息但推理不够"的具体例子；能说出 2026 年标准答案是 RAG + 微调组合拳
- 🔴 危险信号：认为"RAG 够强了不需要微调"或"微调够强了不需要 RAG"

### Q4　Prompt 能替代微调吗？在什么场景下可以，什么场景下不行？

- 🔵 考察点：对 Prompt 能力边界的理解
- 🟢 参考答案要点：① 简单场景可以（格式对齐、少样本学习）；② 复杂场景不行（Prompt 本质是在上下文里教，模型没真正学会）；③ 换个模型 Prompt 就失效，微调是刻进权重里可跨模型迁移
- 🟡 加分项：能说出"Few-Shot Prompt 的 token 成本随复杂度线性增长，微调一次投入长期收益"；能举出 Prompt 失败的边界 case
- 🔴 危险信号：认为 Prompt 无所不能；认为 Few-Shot 可以替代微调

## 模块二：高效微调（LoRA / QLoRA / PEFT）

### Q5　为什么全参数微调在工业界"已死"？LoRA 相比全参数微调的核心优势是什么？

- 🔵 考察点：对 LoRA 核心价值的理解（显存、训练时间、性能恢复率）
- 🟢 参考答案要点：① 全参数微调 7B 模型需 ~56GB 显存，LoRA（r=64）仅需 ~12GB；② LoRA 恢复全量微调 90-95% 性能，显存仅 1/5；③ 训练时间从 12-24h 降到 2-4h
- 🟡 加分项：能背出具体数字（56GB vs 12GB vs 6GB QLoRA）；能说出 LoRA 的数学直觉（权重更新矩阵低秩，用 B·A 近似 ΔW，仅需 2dr 参数）
- 🔴 危险信号：不知道 LoRA 显存节省比例；认为全参数微调仍是主流

### Q6　讲一下 LoRA 的数学原理。为什么低秩近似有效？

- 🔵 考察点：对 LoRA 数学直觉的理解，而非公式推导
- 🟢 参考答案要点：① 权重更新矩阵 ΔW 通常是低秩的（fine-tuning 只在少数方向上调整）；② 用两个小矩阵 B(r×d) 和 A(d×r) 的乘积近似 ΔW；③ 原始 ΔW 有 d×d 个参数，LoRA 只需 2dr 个；④ 当 r=8, d=4096 时仅需 0.4% 的可训练参数
- 🟡 加分项：能解释为什么低秩有效（预训练模型已经学到了丰富的表示，微调只需要在子空间内调整）；能说出 r 的选值经验（8-128）
- 🔴 危险信号：无法解释"低秩"的含义；认为 r 越大越好没有上限

### Q7　QLoRA 相比 LoRA 多了什么？为什么消费级显卡能做 7B 微调？

- 🔵 考察点：QLoRA 三板斧（NF4 量化 + 双重量化 + 分页优化器）
- 🟢 参考答案要点：① 4-bit NF4 量化——专为 LLM 权重分布优化的量化格式，非简单截断；② 双重量化——量化的量化，显存再省 30%；③ 分页优化器——动态分配显存，防止训练峰值 OOM；④ 精度损失 < 2%，显存从 12GB 降到 6GB
- 🟡 加分项：能说出 NF4 利用了正态分布权重的统计特性；能说出"48GB GPU 上微调 65B 模型靠的就是分页优化器"
- 🔴 危险信号：不知道 QLoRA 和 LoRA 的区别；认为量化一定会大幅损失精度

### Q8　LoRA 的超参数怎么选？给一个 7B 模型 + RTX 4090 的推荐配置。

- 🔵 考察点：实战超参数选型能力
- 🟢 参考答案要点：① r=64（32-128 范围，越大效果越好但显存越高）；② lora_alpha=16（通常 2*r 或 16）；③ target_modules 全覆盖（q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj）；④ lora_dropout=0.05；⑤ bias="none"
- 🟡 加分项：能根据显存大小给出不同配置（<8GB → r=16-32 + 梯度累积；12-16GB → r=64 + batch=1-2；>24GB → r=128）；能说出 bnb_config 的完整配置
- 🔴 危险信号：不知道 target_modules 该选哪些层；r 值随意给没有依据

### Q9　LoRA 和 Adapter 怎么选？各有什么适用场景？

- 🔵 考察点：对不同 PEFT 方法差异的理解
- 🟢 参考答案要点：① LoRA 效果更稳定，是 2026 年默认选择；② Adapter 优势是可针对不同任务插入不同适配器、快速切换；③ LoRA 适合单任务深度优化，Adapter 适合多任务 SaaS 平台
- 🟡 加分项：能说出 Prefix Tuning / Prompt Tuning 的适用场景；能给出"先用 LoRA 快速验证，多任务隔离再考虑 Adapter"的实战策略
- 🔴 危险信号：认为所有 PEFT 方法效果一样；不知道 Adapter 存在推理延迟问题

## 模块三：数据构造

### Q10　"1000 条高质量 > 10 万条噪声"——这句话背后的逻辑是什么？

- 🔵 考察点：对数据质量 vs 数量的理解
- 🟢 参考答案要点：① 噪声数据会引入错误 pattern，微调会把这些错误刻进权重；② 高质量数据让模型学到正确的行为模式；③ 数据质量维度：指令清晰度、输出一致性、边界 case 覆盖
- 🟡 加分项：能说出"数据清洗的成本远低于修复一个训歪的模型"；能举出噪声数据导致模型退化的具体例子
- 🔴 危险信号：认为"数据越多越好"；忽略数据质量评估

### Q11　7B 模型不同任务类型的数据量推荐是多少？

- 🔵 考察点：对不同任务数据量门槛的实战经验
- 🟢 参考答案要点：① 工具调用格式对齐：200-500 条；② 领域知识问答：1000-3000 条；③ 代码生成：3000-5000 条；④ 通用对话风格：5000+ 条
- 🟡 加分项：能说出不同任务的 Epoch 推荐（工具对齐 3-5，领域问答 2-3，通用对话 1-2）；能解释为什么工具对齐数据量最少（格式约束强，模型容易学会）
- 🔴 危险信号：所有任务给同一个数据量；不知道 Epoch 的影响

### Q12　数据不够怎么办？有哪些数据增强手段？

- 🔵 考察点：数据稀缺时的应对策略
- 🟢 参考答案要点：① 用 GPT-4 生成合成数据 + 人工校验；② 用现有模型做 Few-shot 生成 + 人工筛选；③ 优先保证质量，1000 条精品 > 10 万条垃圾；④ 数据增强：同义改写、反向翻译、模板生成
- 🟡 加分项：能说出合成数据的风险（模型 bias 放大、多样性不足）；能说出人工校验的比例建议（至少抽检 10%）
- 🔴 危险信号：认为"GPT-4 生成的数据可以直接用不需要校验"

### Q13　微调后效果变差了（灾难性遗忘）怎么办？

- 🔵 考察点：对灾难性遗忘的诊断和应对
- 🟢 参考答案要点：① 降低学习率（1e-5 ~ 5e-5）；② 减少 Epoch；③ 混合原始预训练数据一起训（data mixing）；④ 减小 LoRA 的 r 值（限制可训参数量）
- 🟡 加分项：能说出"灾难性遗忘的本质是梯度更新覆盖了原有知识"；能说出 data mixing 的比例建议（微调数据:原始数据 = 1:1 ~ 1:3）
- 🔴 危险信号：遇到效果变差只会降学习率；不知道 data mixing 策略

## 模块四：知识蒸馏

### Q14　知识蒸馏的核心原理是什么？和微调有什么本质区别？

- 🔵 考察点：对蒸馏原理的理解
- 🟢 参考答案要点：① 蒸馏本质：让小模型（学生）学大模型（教师）的软输出（概率分布），不只学硬标签；② 用 KL 散度衡量两者差距；③ 微调目的是让模型适应新任务，蒸馏目的是让模型变小变快
- 🟡 加分项：能说出"软标签包含了教师模型的不确定性和信心水平，比硬标签信息量更大"；能说出蒸馏的损失函数 = α·KL(学生||教师) + (1-α)·交叉熵(学生, 硬标签)
- 🔴 危险信号：认为蒸馏就是"用小模型重新训练"；不知道软标签和硬标签的区别

### Q15　什么时候用蒸馏而不是直接用小模型微调？

- 🔵 考察点：蒸馏 vs 小模型微调的决策能力
- 🟢 参考答案要点：① 小模型容量有限，直接微调学不会复杂模式；② 蒸馏让小模型从大模型那里"继承"推理能力；③ 蒸馏效果远好于从头训小模型
- 🟡 加分项：能说出"蒸馏的精度损失通常 < 3%，推理速度提升 2-5 倍"；能说出 Agent 场景下蒸馏的价值（高并发子任务用小模型，大模型只处理复杂推理，成本降 60%+）
- 🔴 危险信号：认为小模型微调和蒸馏效果一样

### Q16　KD-LoRA 是什么？为什么是 2026 年前沿方案？

- 🔵 考察点：对前沿混合方案的理解
- 🟢 参考答案要点：① KD-LoRA = LoRA 微调 + 知识蒸馏的组合；② 先用 LoRA 让大模型适应领域，再用蒸馏把能力灌进小模型；③ 微调管精度，蒸馏管规模
- 🟡 加分项：能说出"微软 KD-LoRA 论文的核心思路"；能举出端侧部署的实际场景
- 🔴 危险信号：不知道 LoRA 和蒸馏可以组合使用

## 模块五：Agent 场景下的特殊考量

### Q17　Agent 到底该不该微调？不同场景怎么选？

- 🔵 考察点：Agent 场景下的微调决策能力
- 🟢 参考答案要点：① 工具调用格式不稳定 → LoRA 微调 200-500 条；② 领域知识问答 → RAG 为主 + LoRA 辅；③ 对话风格/人设固定 → Prompt 就够；④ 代码生成 → LoRA 3000-5000 条；⑤ 端侧部署 → 蒸馏
- 🟡 加分项：能说出每个场景的具体理由（为什么工具调用必须微调——Prompt 兜不住格式一致性）；能结合自己的项目经验说明
- 🔴 危险信号：认为 Agent 不需要微调；认为所有 Agent 场景都应该微调

### Q18　工具从 5 个增到 80 个后误调率上升，怎么诊断和解决？

- 🔵 考察点：工具规模扩展时的系统设计能力
- 🟢 参考答案要点：① 加参数校验层——工具 Schema 强类型校验，格式不合法让 LLM 重生成；② 工具预筛选——向量检索 Top-5 相关工具再让 LLM 选；③ Dry-run 模式——正式调用前先模拟；④ 关键调用人工兜底——删除/支付等高危操作必须人工确认；⑤ LoRA 微调工具选择能力——200-500 条高质量数据
- 🟡 加分项：能说出"工具描述的质量比数量更重要"；能给出具体的向量检索实现方案（用工具描述的 embedding 做相似度匹配）
- 🔴 危险信号：只会说"加更多 Prompt"；不知道 Dry-run 和人工兜底的必要性

### Q20　QLoRA 和 LoRA 怎么选？给出决策标准。

- 🟡 加分项：能说出"能不能做取决于有没有卡，不是取决于想不想"；能给出不同显卡的显存预算明细
- 🔴 危险信号：不知道显存门槛；认为 LoRA 和 QLoRA 可以随意互换
